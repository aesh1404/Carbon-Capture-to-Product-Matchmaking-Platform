Confirmed the same visually in-browser: the emitter's "My Listings" table showed `0 / 1000` / `CLOSED`, and both accepted match cards independently showed correct per-match transacted volume and recalculated cost.
- Threshold for auto-close is `< 1.0` remaining tons (not just exactly 0), per the spec's "e.g. < 1 ton" — covered by a dedicated test (`accept_closesListingWhenRemainingVolumeFallsBelowOneTonThreshold`, leaves 0.5 tons and confirms `CLOSED`).

## API Reference

| Method | Path | Description |
|---|---|---|
| GET | `/api/cities` | List the 22 supported city names (alphabetical), for every city dropdown. |
| POST | `/api/users` | Register a user (EMITTER or BUYER) with a `city` name (stored verbatim, alongside resolved lat/lng). 400 on missing fields, invalid role, or unsupported city. |
| GET | `/api/users` | List users. Optional query param `role` (`EMITTER`/`BUYER`); omitted = all. 400 on an invalid role value. |
| GET | `/api/users/{id}` | Fetch a user by id. 404 if not found. |
| POST | `/api/listings` | Create a listing with a `city` name (this listing's own site — stored verbatim, independent of the emitter's registered city). 400 on invalid volume/purity/price, unsupported city, or a non-EMITTER/nonexistent `emitterId`. |
| GET | `/api/listings` | List listings. Optional query params: `minPurity`, `maxPrice`, `status` (default `ACTIVE`). |
| GET | `/api/listings/{id}` | Fetch a listing by id. 404 if not found. |
| GET | `/api/listings/{id}/matches` | Optional query param `status`. Default (no param): `REQUESTED` only — "Incoming Matches", actionable. `status=FINAL`: `ACCEPTED`/`REJECTED`/`CANCELLED`/`REVERTED` only — "Order Status" archive. `status=<name>`: that one status. An undecided (`SUGGESTED`/`REQUESTED`) match is only ever included while the listing is still `ACTIVE` and its own request still `OPEN` — otherwise it's stale and filtered out regardless of the status filter. Marks any unviewed `CANCELLED` matches as viewed as a side effect. 404 if listing not found, 400 on an invalid status value. |
| GET | `/api/listings/quick-browse` | "Quick Browse": plain filter + sort, no compatibility scoring. `buyerCity` required, `minPurity`/`maxDistanceKm` optional. `ACTIVE` listings with `remainingVolumeTons > 0` only, sorted by distance ascending (closest first). 400 on an unsupported `buyerCity`. |
| POST | `/api/listings/{id}/quick-request` | "Request This Listing" from Quick Browse. Body `{buyerId, minVolumeNeeded}`. Creates a minimal `CarbonRequest` (permissive defaults: `minPurityRequired=0`, `maxDistanceKm=100000`, `maxBudgetPerTon=1000000`) and an already-`REQUESTED` `Match` against it in one call — flows straight into "Pending Requests"/"Incoming Matches" like any other request. 409 if the listing is no longer `ACTIVE` or if `minVolumeNeeded` exceeds its `remainingVolumeTons`, 404 if listing missing, 400 on a non-`BUYER`/nonexistent `buyerId` or non-positive `minVolumeNeeded`. |
| POST | `/api/requests` | Create a carbon request. 400 on invalid volume/purity/budget/distance or a non-BUYER/nonexistent `buyerId`. No location field — distance is always computed from the buyer's own registered `User.locationLat/Lng`. |
| GET | `/api/requests` | List carbon requests. Optional query param `buyerId`; omitted = all. |
| GET | `/api/requests/{id}` | Fetch a request by id. 404 if not found. |
| GET | `/api/requests/{id}/matches` | "Find Matches": fresh, actionable, unrequested (`SUGGESTED`-only) recommendations for this one request. Runs fresh matching (skipped entirely once the request is no longer `OPEN`); `>= 50` compatibility only. Never returns a `REQUESTED` or decided match, even a moment old — those live in the endpoint below now. No `status` param (there's only one thing this endpoint is for). |
| GET | `/api/requests/{buyerId}/sent-matches` | Every match across *all* of this buyer's requests that they've actually acted on — a passive `SUGGESTED` candidate is excluded (that's the job of the endpoint above). Optional `status`: default = everything sent (`REQUESTED`/`ACCEPTED`/`REJECTED`/`CANCELLED`/`REVERTED`); `status=REQUESTED` = "Pending Requests"; `status=FINAL` = "Order Status" archive. Marks unviewed buyer-notify statuses as viewed as a side effect (only for whatever subset the given filter actually returns). 400 on an invalid status value. |
| POST | `/api/matches/{id}/request` | Buyer expresses interest in a `SUGGESTED` match → `REQUESTED`. 404 if match missing, 409 if already decided. |
| POST | `/api/matches/{id}/accept` | Accept a match → match `ACCEPTED` with `transactedVolumeTons` set (stock deducted **here and only here**), listing's `remainingVolumeTons` reduced (status `CLOSED` if that drops under 1 ton, else stays `ACTIVE`), request `MATCHED`. **Never partial** — `transactedVolumeTons` is always the buyer's full ask. 404 if match missing, 409 if already decided, if the listing is no longer `ACTIVE` / the request no longer `OPEN` (claimed elsewhere in the meantime), **if `remainingVolumeTons < request.minVolumeNeeded`** (refused rather than under-filled, nothing mutated), or if a concurrent accept won the race for the same stock (optimistic-lock failure on `Listing.version`). |
| POST | `/api/matches/{id}/reject` | Reject a match → match `REJECTED` (listing/request/stock all untouched). 404 if match missing, 409 if already decided, or if the listing is no longer `ACTIVE` / the request no longer `OPEN`. |
| POST | `/api/matches/{id}/cancel` | Buyer withdraws their own already-`REQUESTED` interest → match `CANCELLED` (stock untouched — nothing was ever deducted). Reopens the request to `OPEN` **unless it is already `MATCHED` by a different accepted match**, which would otherwise allow the same request to be fulfilled twice. 404 if match missing, **409 unless `match.status == REQUESTED`** (a `SUGGESTED` candidate can't be cancelled — nothing's been "sent" yet). |
| POST | `/api/matches/{id}/revert` | Undoes a previously-`ACCEPTED` match → match `REVERTED`, `transactedVolumeTons` added back to the listing's `remainingVolumeTons` (capped at `totalVolumeTons`), listing reopened to `ACTIVE` unless the restored amount is still under the 1-ton auto-close threshold, request unconditionally reopened to `OPEN`, linked order flipped to `REVERTED`. 404 if match missing, **409 unless `match.status == ACCEPTED`**, and **409 once the order's `deliveryStatus` has moved past `CONFIRMED`** (already dispatched). |
| GET | `/api/matches/unviewed-count` | "NEW" badge peek — pass exactly one of `buyerId`/`emitterId`. Returns `{count}` of unviewed, notify-worthy status changes (buyer: `ACCEPTED`/`REJECTED`/`REVERTED`; emitter: `CANCELLED`) without marking anything viewed. 400 if zero or both params given. |
| GET | `/api/orders/{id}` | Full order detail — the permanent settlement record created when a match is accepted. Includes `deliveryStatus`. 404 if not found. |
| GET | `/api/orders/by-user/{userId}` | All orders where this user is either the emitter or the buyer, newest first. Empty list if none (no existence check on `userId`). |
| POST | `/api/orders/{id}/delivery-status` | Advance `deliveryStatus` exactly one step forward (`CONFIRMED → IN_TRANSIT → DELIVERED`). Body `{"status": "..."}`. 409 on skip-ahead, backward, past `DELIVERED`, or if the order's own `status` isn't `CONFIRMED` (e.g. `REVERTED`). 400 on an invalid status value, 404 if order not found. |
| GET | `/api/analytics/summary` | Platform-wide impact metrics: listing/request/order counts, `totalVolumeTransactedTons`/`totalValueTransacted`/`totalCo2DivertedTons` (from `CONFIRMED` orders only), `topCaptureMethod` (highest total volume across `ACTIVE` listings), `ordersByMonth` (`[{month, count, volumeTons}]`). |

> The fullest version of this reference — with request/response **shapes** for every endpoint — now lives in [`README.md`](./README.md#api-reference). The table above is the behavioural detail (status codes, side effects, filter semantics); the README is the contract.

All error responses share the shape `{ "error": "<message>", "status": <code> }`. Every `MatchResponseDTO` now also carries `statusMessage` (null for `SUGGESTED`/`REQUESTED`, a human-readable sentence otherwise — see the Completed entry above for exact wording per status/viewpoint), `viewed` (boolean), `emitterCity`, `buyerCity`, and `orderId` (null unless the match is `ACCEPTED`/`REVERTED`). `costBreakdown` carries `volumeTons` alongside the money — the volume every figure in it was priced from (the buyer's ask before acceptance, the transacted volume after), so a client can never render a quote beside the listing's much larger size and let the two be confused. `ListingResponseDTO`/`UserResponseDTO` deliberately do **not** expose `locationLat`/`locationLng` — coordinates are an internal derivation of `city`, and distances always reach the client pre-computed.

      DeliveryProgress.jsx    — read-only 3-step indicator (Confirmed → In Transit → Delivered), reached steps highlighted; Delivered renders as an explicitly locked node while payment is outstanding
      ThemeToggle.jsx         — light/dark switch (sun/moon + label); `floating` variant for the pre-login screens, which have no topbar
    pages/
      RoleSelector.jsx        — thin hash router over the two pre-login views (`#/login/emitter`, `#/login/buyer`); clears the hash on login so a later logout lands on the landing page
      LandingPage.jsx         — "Are you an Emitter or a Buyer?" chooser, two large role cards
      LoginPortal.jsx         — username/password sign-in + sign-up, themed per role (emerald/Factory "Emitter Portal · Supply side" vs teal/Leaf "Buyer Portal · Demand side"); no roster of existing users
      Payment.jsx             — simulated checkout: order number, amount due, UPI/Net Banking/Card, ~1.8s fake processing, then success. Calls `payOrder(orderId)` on completion and skips itself if already PAID. Disclaimer on both screens — nothing is processed
      EmitterDashboard.jsx     — 3 tabs: **Incoming Matches** (REQUESTED-only, Accept/Reject), **My Listings** (create-listing form + table, unchanged), **Order Status** (final-status archive, Revert only on ACCEPTED, delivery-status progress + advance button, "NEW" badge on the tab itself, Order History ledger nested inside)
      BuyerDashboard.jsx       — 4 tabs: **Find Matches** (SUGGESTED-only recommendations + Create Request form), **Quick Browse** (plain distance filter+sort against `/api/listings/quick-browse`, "Request This Listing" per result), **Pending Requests** (REQUESTED-only, Cancel is the only action), **Order Status** (final-status archive, View Receipt on ACCEPTED, read-only delivery-status progress, "NEW" badge on the tab itself, Order History ledger nested inside).       ImpactDashboard.jsx      — platform-wide, role-independent: 4 stat cards (CO2 diverted, value transacted, active listings, confirmed orders), Recharts bar chart of `ordersByMonth`, top capture method, the required impact note. Reads `GET /api/analytics/summary`.
    utils/
      format.js               — `formatCurrency`/`formatCurrencyWhole`/`formatNumber`/`formatKm`, all on one pinned `en-IN` formatter (a bare `.toLocaleString()` renders differently per viewer locale)
      numberInput.js          — `blurOnWheel`, applied to every number input so a scroll over a focused field can't silently change a price
      theme.js                — `initialTheme()` / `applyTheme()`; writes `<html data-theme>` + `color-scheme` and persists to `localStorage` (every access guarded)
    App.jsx                  — top-level user state, role-based view switch, header/nav (brand + user info + theme toggle + Switch User) plus a `.header-nav` segmented control ("My Dashboard" / "Impact Dashboard", role-independent); `receiptOrderId` / `paymentOrderId` state swaps the dashboard out for `<Receipt>` / `<Payment>` when set (no router in this app - plain state-based view switching, per the brief)
